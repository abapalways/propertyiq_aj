# PropertyIQ

A property-matching search agent built for the PropertyIQ Challenge (Team Beyond AI Engineering course).

PropertyIQ combines exact metadata filtering, semantic + keyword hybrid search, and an NLI-based
contradiction check to return real-estate listings that genuinely match a buyer's stated criteria —
not just listings that _look_ similar to the query. It runs as a chat agent in a Gradio UI, with
tool-calling for mortgage calculations and comparable-sale lookups, session memory for rejected
listings, and fair-housing guardrails on every request.

## Prerequisites

- Python 3.13
- API keys for:
  - **Google Generative AI** (Gemini embeddings) — used for the vector store and search
  - **Groq** (LLM) — used for the chat agent
- (Optional) A [LangSmith](https://smith.langchain.com/) account, for tracing

## Setup

1. **Clone the repo and enter it**

   ```bash
   git clone <repo-url>
   cd propertyiq_aj
   ```

2. **Create and activate a virtual environment**

   ```bash
   python3.13 -m venv .venv
   source .venv/bin/activate
   ```

3. **Install dependencies**

   ```bash
   pip install -r requirements.txt
   ```

   > If `requirements.txt` isn't present or out of date, install directly:
   > `pip install langchain langchain-community langchain-google-genai langchain-groq langchain-ollama gradio sentence-transformers guardrails-ai python-dotenv rank_bm25`

4. **Create a `.env` file at the project root** with:

   ```
   GOOGLE_API_KEY=your_google_api_key
   GROQ_API_KEY=your_groq_api_key
   LANGCHAIN_TRACING_V2=true
   LANGCHAIN_PROJECT=PropertyIQ_AJ
   LANGCHAIN_API_KEY=your_langsmith_api_key   # optional, only needed if tracing is enabled
   ```

5. **Build the vector index** (run once, and again any time `data/listings_corpus.md` or
   `scripts/dimensions_config.py` changes)

   ```bash
   cd scripts
   python ingest.py
   ```

   This reads `data/listings_corpus.md`, extracts and enriches fuzzy dimensions
   (school quality, condition) per listing, and writes the FAISS index to `faiss_index/`.

6. **Run the app**
   ```bash
   python chat_app.py
   ```
   This launches a local Gradio UI (and a temporary public share link) where you can chat as one
   of the seeded buyer profiles or as a guest.

## Project structure

```
propertyiq_aj/
├── data/
│   ├── listings_corpus.md       # Source listing/neighborhood data for RAG
│   ├── buyer_profiles.json      # Synthetic buyer profiles, preferences, rejection history
│   └── sold_comps.json          # Comparable sold-listing data for the comps tool
├── docs/
│   ├── guardrails.md            # Guardrail rules and their requirements mapping
│   └── task19_guardrail_test.md # Guardrail test evidence
├── faiss_index/                 # Generated by ingest.py — not committed, rebuild locally
├── scripts/
│   ├── ingest.py                # Builds the FAISS index; extracts + enriches fuzzy dimensions
│   ├── dimensions_config.py     # Single source of truth for fuzzy dimension keywords/phrases
│   ├── search.py                # Core search: hard filters, RRF (dense + BM25), NLI check
│   ├── tools.py                 # calc_mortgage, get_comps (deterministic, no LLM)
│   ├── memory.py                # Rejected-listing memory: reject/undo/reset, semantic extraction
│   ├── chat_agent.py            # LLM + tool binding, system prompt construction
│   ├── chat_app.py              # Gradio UI: chat, agent trace, debug analysis panel
│   └── guardrails_check.py      # Fair-housing and on-topic input validators
└── README.md
```

## A note on known gaps

- `requirements.md` (the original project requirements doc, referenced by several task
  definitions and by comments in the codebase) is missing from this repo. Sample queries and
  expected-answer tables reconstructed from other sources should be treated as best-effort,
  not the original spec.
- The embedding provider (Google Generative AI) can occasionally return a transient `503` error;
  there's currently no automatic retry/fallback for this in `search.py`.
